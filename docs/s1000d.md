# S1000D projects, publication modules and applicability

## Project view

The left panel has two tabs, *Structure* and *Project*. Open the Project tab
with *View › Project* (or *Tools › Project folder…*), then choose a folder with
*Folder…*. Xylem reads every `.xml` file in it and in its sub-folders, on a
background thread, and lists the data modules and publication modules it finds
with their code, issue and in-work number, language and title. Files that are
not data or publication modules are skipped; files that are not well-formed are
counted as unreadable. The folder is remembered and scanned again the next time
the tab is opened.

- Type in the filter box to narrow the list. Every word must occur in the code,
  title, issue (`001-00`), language (`en-US`) or file name.
- Double-click a row (or select it and press *Open*) to open the module.
- *Rescan* reads the folder again after files changed outside Xylem.

### Check references

*Check references* looks at every `dmRef` and `pmRef` in every module of the
folder and reports:

- references to a module that is not in the folder (in red). When the
  reference names a language, only modules in that language count. When it
  names an issue that is newer than any in the folder, it is reported too;
- references that name an issue older than the newest issue of that module in
  the folder (in orange);
- modules for which a newer issue of the same code and language is in the
  folder (outdated, in orange).

A reference without an issue resolves to the newest issue, as when following
it with Ctrl+click. References to the BREX are listed apart, behind *Include
BREX references*, because most projects use the default S1000D BREX without
keeping a copy of it in the folder.

Click a result to open the module with the reference selected.

### Insert reference

Put the caret where a reference belongs (for example in a publication module's
`pmEntry`), select a module in the list and press *Insert reference*, or use
the row's context menu. Xylem inserts a complete reference:

```xml
<dmRef>
  <dmRefIdent>
    <dmCode .../>
    <issueInfo issueNumber="001" inWork="00"/>
    <language languageIsoCode="en" countryIsoCode="US"/>
  </dmRefIdent>
  <dmRefAddressItems>
    <dmTitle><techName>...</techName><infoName>...</infoName></dmTitle>
  </dmRefAddressItems>
</dmRef>
```

or the equivalent `pmRef` for a publication module. Like *Insert element*, it
goes at the caret when the schema allows it there, otherwise after the nearest
enclosing element where it is allowed. The button is disabled when no such
place exists. References are written in issue 4.0+ markup, so the button is
disabled in 2.x and 3.0 modules.

## Publication modules

*File › New S1000D module…* offers *Publication module* as a schema for issues
4.0 to 6.0. The new module has one `pmEntry` with a placeholder `dmRef`,
because the schema requires every entry to reference something; replace it
with references from the project view. Issues 4.0 and 4.0.1 have no BREX
reference in a publication module's status section, so none is written.

## Applicability

*View › Applicability…* lists the product attributes and conditions named by
the document's `assert` elements, each with a chooser of the values those
asserts mention (both ends of a range are offered), or type any value in the
box beside it. Choose values and the
content that does not apply under them is drawn faded, or left out of the view
with *Hidden*. The document itself is not changed.

How it is evaluated:

- An element with `applicRefId` applies when the `applic` it names (in
  `referencedApplicGroup`) evaluates true. Several identifiers separated by
  spaces must all apply.
- When the module-level `applic` in the status section evaluates false, the
  whole `content` is treated as inapplicable.
- `applicPropertyValues` may list values separated by `|` and ranges written
  `low~high`. Ranges compare as numbers when both ends and the value are
  numbers, and as text otherwise (so `N001~N099` works for serial numbers of
  equal length).
- `evaluate` combines its children with `andOr="and"` or `"or"`.
- A property left at "any" makes its asserts unknown, and unknown counts as
  applicable. The filter only removes what the chosen values certainly
  exclude. Asserts and `applic` elements with only display text always apply.

Older issues:

- **Issue 3.0** has the same model under other names: `assert` with
  `actidref`, `actreftype` and `actvalues`, `evaluate` with `operator`,
  statements collected in `inlineapplics`, and elements pointing at them with
  `refapplic`. Xylem evaluates these too.
- **Issues 2.0 to 2.3** state applicability with `type` and
  `model`/`version` elements. These are descriptions for the reader with no
  defined evaluation, so the dialog lists no properties and nothing is
  filtered.
